Reading whether an agent will execute a planted memory note

Linear probes on gpt-oss-20b's mid layer activations, tested against text readers, a guard model, sparse autoencoder features and the Jacobian lens, on 148 Sleeper Attack memory poisoning cases.

Raghav Agarwal with Huy PhamMentors Enyi Jiang and Himnish Hunma14 November 2026
Pre-registered phase 1 complete Phase 2 analyses complete (exploratory) SAE and J-Lens readouts (exploratory) Attention baselines, Jev rerun, multi model: built, need GPU or key

Summary

An attacker plants an instruction in an agent's long term memory. Later a harmless user request makes the agent retrieve it, and the agent may carry out the planted action. We asked whether the agent's own activations at that moment, before it writes anything, show whether it will act, and whether they show more than the words of the prompt already do.

  • Telling a planted instruction from a harmless record is easy, and text alone does it. A probe scores AUROC 0.998 to 1.000 and so does a bag of words reader. This only validates the pipeline.
  • Whether the agent will execute the note is the real question, and wording dominates it. The same note executes in 2% to 78% of rollouts depending only on how it is phrased, so every fair comparison has to hold wording fixed.
  • Within the same wording, the probe predicts execution better than text, clearly so on unseen domains. Probe 0.821 vs full prompt TF-IDF 0.621 when whole domains are held out (difference +0.200 [+0.083, +0.318]), and 0.909 vs 0.805 on held out cases when trained on the execution rate (+0.104 [+0.035, +0.173]). On the smaller pre-registered training split the gap is not significant.
  • A guard model does not see it. Jev scored 0.47 on predicting execution where the probe scored 0.98 on the same notes. It flags every planted instruction as malicious, which is correct but says nothing about whether this model will obey.
  • The model verbalizes the note's status, not its decision. Jacobian lens readouts at the note say "reminder, checklist, task" for planted instructions and "completed, earlier, canceled" for records. Neither those readouts nor the top SAE features carry the execution signal the dense probe finds.

Everything after the pre-registered phase 1 report is exploratory. Several analysis choices (the execution rate target, within wording metrics) were made after seeing phase 1. The next dataset should pre-register them.

Finding 1. Wording decides most of whether a note is executed

The six poisoned wordings carry the same instruction. Only the phrasing changes, yet the mean execution rate ranges from 2% to 78%. When an agent does execute a note, it almost always also completes the user's task, so the attack hides inside normal looking behaviour.

Finding 2. Poisoned vs benign twin is solved, and the words give it away

On every held out set the probe scores 0.998 to 1.000, and TF-IDF on the note scores 1.000. The model separates the two from very early layers on. The six poisoned notes the probe mistakes for twins all use wording 4, the wording that is executed about 2% of the time.

Finding 3. The probe predicts execution on new wordings and domains

Among poisoned notes only, a probe trained on the training split predicts which notes reach execution. Overall AUROCs look high for everything because wording alone already sorts most notes, which is why section 4 holds wording fixed.

Calibration is reasonable: expected calibration error 0.066 on E1 and 0.098 on E2, Brier scores 0.042 and 0.103. Averaging the two probe positions gives 0.961 on E1; adding the text model does not help (0.947).

Within the same case on E1, the probe ranks wording 5 above wording 4 in all 11 cases where they behave differently, matching behaviour. Every text baseline ranks them the other way. That is one comparison between two wordings, so it is suggestive only.

Why we think we see these readings

These are our best explanations, with how confident we are in each. The ones marked medium or low are hypotheses the next experiments test.

Poisoned vs twin is trivial because the two differ in obvious words High

Poisoned notes say things like "still pending, complete it now"; twins say the action was done. Any reader keyed on those words separates them. The model encodes the same distinction early because attention carries the note's content to later positions within one or two layers. The J-Lens readouts ("task, reminder" vs "completed, earlier") show the model represents it in words too.

Text readers fail within wording because they memorize vocabulary, not the decision Medium

Once wording is fixed, what decides execution is how the planted action relates to the user's request and the tools at hand: whether it is plausible in context, whether it fits the domain, how disruptive it is. TF-IDF can only count words and phrases, so it learns which domains and actions tend to be executed. That transfers poorly to unseen domains, which is exactly where it falls to 0.62. The probe reads a representation the model has already formed by combining note, request and context, which is closer to the decision itself.

The probe reads a graded disposition, not a yes/no switch Medium

Training on the execution rate helps the probe (0.860 to 0.909) but barely helps text (0.793 to 0.805), and the probe correlates better with the rate. The yes/no label is noisy: 160 notes labelled resisted were executed at least once in 8 tries. A probe whose score tracks the model's propensity benefits from soft labels; a text model has no propensity to track.

The gap is smaller on the 512 note split because it has less to work with Medium

That split has 4 wordings, two of which are executed most of the time (wording 0 at 92% of notes), leaving few executed vs resisted pairs inside the same wording. Nested model selection also removed a small optimistic bias, lowering the gap from +0.062 to +0.035. With 888 notes and all 6 wordings there are enough within wording pairs to see the difference.

Wording 4's poisoned notes look like twins to the probe because the model does not take them seriously Low to medium

The only poisoned notes the probe misclassified are in the wording executed 2% of the time. One reading: the status direction partly encodes "how much this reads as an open task to me", which overlaps with the disposition to act.

The guard model scores low because it answers a different question High

Every poisoned note is malicious, so a correct guard flags all of them, executed or not. Whether gpt-oss-20b obeys a particular note is a fact about this model's internals, not about the text, so a separate model reading the text cannot know it.

SAE features and lens readouts miss the execution signal for several possible reasons Low

The signal may be spread across many weak features, sit outside the top 100 we could retrieve, live in the SAE's reconstruction error, or be weakened by the shortened prompts. For the lens, the decision may not be verbalizable at these positions; gpt-oss reasons before acting, so the decision may form later, in its reasoning tokens. A steering experiment and the SAE weights run locally will tell these apart.

Attention based detectors will likely struggle here Prediction

Attention Tracker and AttnDA look for attention leaving the user's instruction. Here the agent executes the payload alongside the task, not instead of it (29.2% of rollouts do both, 0.2% only the payload), so attention to the task may not drop. Half of gpt-oss-20b's layers also only see the last 128 tokens, while the user request sits 123 to 818 tokens back. This is the RQ1 test still to run.

Built and tested, not yet run

  • Attention baselines on real attention. Attention Tracker (head selection on 30 calibration sentences, plus heads fitted on our labels), AttnDA (all 1,536 heads, shrinkage LDA, plus full attention layers only), AttentionDefense (system prompt attention, random forest), and the last layer FC baseline. About 25 minutes on one A100.
  • Fair Jev rerun. About 1,000 API calls for both tasks on E1 and E2, roughly 5 cents.
  • Multi model pipeline. Renders all 1,924 prompts in each model's own chat format, checks them token for token against vLLM, samples each model's own behaviour, captures activations, and runs the same pre-registered analysis at the same relative depth as layers 14 to 19 of 24. A model is analysed only if at least 50 notes are executed, at least 50 resisted, and at least 2 wordings contain both.
  • Steering test. Push the residual stream along the probe direction (−4 to +4 standard deviations), along a random direction as a control, and remove the direction entirely, then measure how often the first response executes the note.
  • Cluster scripts for DeltaAI (waiting for access) and RunPod.

Limitations

  • One model, one attack family, one trigger turn per prompt, and canned tool results after the first step.
  • 148 cases and 6 wordings; intervals are wide and several comparisons rest on few wordings.
  • Results after phase 1 are exploratory and some analysis choices followed phase 1 results.
  • The probe is correlational until the steering test runs.
  • The note is always in context, so this is detection at the trigger turn, not of a note waiting for its trigger.
  • The Neuronpedia analyses use small samples and, for SAEs, approximate prompts.
